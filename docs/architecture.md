# Архитектура

## Состав проекта

- `cmd/bot` - точка входа.
- `internal/app` - сборка приложения и lifecycle фоновых задач.
- `internal/config` - конфигурация из переменных окружения.
- `internal/storage` - PostgreSQL, миграции, advisory locks, репозиторий.
- `internal/vk` - VK API, Long Poll, отправка сообщений и attachments.
- `internal/summary` - выбор сообщений, prompt, публикация дайджеста.
- `internal/llm` - интерфейс LLM и клиенты `stub` / `openai_compat`.
- `internal/imagegen` - генерация изображений и watermark `DDD`.
- `migrations` - SQL-миграции, встроенные в бинарник.

## Поток данных

1. Приложение открывает PostgreSQL pool и применяет миграции.
2. VK Long Poll получает события `message_new` и `message_event`.
3. Входящие сообщения сохраняются в `messages` по отдельному `peer_id`.
4. После каждого сообщения бот проверяет, готов ли автоматический дайджест.
5. Ручная команда запускает тот же pipeline для текущей беседы.
6. Summary-сервис выбирает необработанный диапазон сообщений.
7. На диапазон берется PostgreSQL advisory lock.
8. Сообщения фильтруются простыми правилами: пустые, слишком короткие, ссылки без текста и строки без букв/цифр отбрасываются.
9. Prompt строится из стабильных инструкций, предыдущих summary и текущих сообщений в хронологическом порядке.
10. LLM возвращает текст дайджеста.
11. Если включены изображения, отдельный LLM-вызов готовит image prompt, затем image-провайдер генерирует картинку.
12. После генерации на картинку накладывается watermark `DDD`.
13. Бот публикует текст и, если получилось, attachment в VK.
14. После успешной публикации диапазон сохраняется в `processed_summary_batches`, а обработанные сообщения удаляются из `messages`.

## База данных

Основные таблицы:

- `messages` - необработанные сообщения бесед.
- `processed_summary_batches` - опубликованные дайджесты и статистика LLM/image usage.
- `summary_chat_state` - состояние автопубликации по беседам.
- `summary_issue_counters` - номер выпуска отдельно для каждого `peer_id`.
- `schema_migrations` - примененные миграции.

Идемпотентность приема сообщений обеспечивается уникальностью `(peer_id, source_message_id)`.

Повторная публикация одного диапазона блокируется уникальностью `(peer_id, first_message_id, last_message_id)` и advisory lock.

## Миграции

Миграции выполняются при старте приложения.

Runner защищен PostgreSQL advisory lock `vk_chat_digest_bot_migrations`, поэтому параллельный старт нескольких инстансов не запускает DDL одновременно. Проверка `schema_migrations`, выполнение SQL и запись версии происходят внутри защищенной секции.

## Фоновые задачи

Manual и auto summary запускаются как фоновые задачи внутри `MessageIngestionService`.

Задачи привязаны к lifecycle context приложения:

- при shutdown новые задачи не стартуют;
- активные задачи получают cancel;
- `App.Run` ждет завершения активных задач перед закрытием PostgreSQL pool.

Это защищает от работы с закрытым repository и от частично выполненных операций при остановке контейнера.

## Long Poll

Long Poll обрабатывает ошибки транспорта отдельно от ошибок обработки update.

Если обработчик одного сообщения временно ошибся, update повторяется с короткими задержками. После исчерпания retry ошибка логируется, update пропускается, а обработка следующего update продолжается. Ошибка одного сообщения не роняет весь consume loop.

`ts` обновляется после обработки всего пакета updates.

## LLM

В коде используется общий интерфейс:

```go
type Client interface {
    GenerateSummary(ctx context.Context, input GenerateSummaryInput) (GenerateSummaryOutput, error)
    Provider() string
}
```

Режимы:

- `stub` - локальная заглушка для проверки запуска.
- `openai_compat` - chat-completions API, совместимый с OpenAI.

Usage сохраняется, если провайдер вернул счетчики:

- input tokens;
- cached input tokens;
- output tokens;
- latency.

## Изображения

Pipeline изображения:

1. Готовый summary передается в отдельный image-prompt LLM.
2. Полученный prompt отправляется image-провайдеру.
3. Генерируется одно изображение без текста.
4. Код накладывает полупрозрачный watermark `DDD` в правый нижний угол.
5. Картинка загружается в VK как photo attachment.

Картинка не хранится на диске приложения.

Если генерация или загрузка изображения не удалась, бот публикует текстовый дайджест без картинки и пишет предупреждение в лог.

## Статистика

Команда debug читает агрегаты из `processed_summary_batches`:

- количество опубликованных дайджестов;
- количество чатов;
- input/output tokens;
- средняя latency;
- примерная стоимость;
- отдельная статистика по изображениям;
- PNG-график input/output за последние 7 дней.
